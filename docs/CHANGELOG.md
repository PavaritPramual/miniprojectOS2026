# CoreSpace — ประวัติและสถานะการพัฒนา

เอกสารนี้บันทึก **สิ่งที่มีในต้นแบบ** แยกจาก **สิ่งที่ทีมวางแผนทำต่อ** รายละเอียดเวอร์ชันส่งงานให้ยึด [SPEC.md](SPEC.md) และผลทดสอบที่บันทึกหลังพัฒนา ไม่ใช้ข้อความหรือ checkbox เก่าเป็นหลักฐานว่าโปรแกรมผ่านการตรวจรับ

## ต้นแบบปัจจุบัน (Python/Win32 + เว็บ)

| ส่วน | สิ่งที่เห็นในโค้ด | สถานะหลักฐาน |
| --- | --- | --- |
| เว็บ | หน้า tree ฝั่งซ้าย, ตารางไฟล์, ปุ่ม Scan และ Reveal; Vue/Tailwind โหลดจาก CDN | มีโค้ด แต่การกดปุ่มครบทุกกรณียังไม่ได้ยืนยัน |
| Scanner | Python `queue.Queue` และ worker threads; Win32 directory enumeration ผ่าน `ctypes` | เคยสแกนโฟลเดอร์ `static` ขนาดเล็กได้ 3 ไฟล์; ยังไม่ใช่ C/POSIX |
| ขนาด | Logical จาก metadata; Allocated/Slack จากสูตร cluster และเกณฑ์ resident file คงที่ | เป็นแบบจำลอง **ไม่ใช่ผลวัด Allocated จริง** |
| Tree data | `convert_to_tree_view_data()` มี `max_depth=6` ใน working tree ที่ตรวจเมื่อ 30 ก.ย. | ลึกกว่านี้อาจไม่ถูกส่งให้หน้าเว็บ; ต้องแก้และทดสอบในงานทีม |
| Benchmark | มีสคริปต์ benchmark | ยังไม่มีหลักฐานเวลา/หน่วยความจำของเวอร์ชัน C/POSIX บนเครื่องเดโม |

ต้นแบบเคยมีเอกสารใช้คำว่า “เสร็จ”, “เร็วกว่า”, “60 FPS”, “RAM ต่ำกว่า 50 MB”, “ไม่มี deadlock 100%” หรือ “ขนาดบนดิสก์แม่นยำ” โดยไม่มีผลทดสอบแนบ คำเหล่านี้ถือเป็น **ข้อกล่าวอ้างเดิมที่ยังไม่ยืนยัน** ไม่ควรอยู่ในสไลด์/รายงานในรูปข้อเท็จจริง เว้นแต่ทีมทำการวัดหรือพิสูจน์ตามกรณีแล้ว

## งานที่จะพัฒนาเพื่อส่งวิชา

1. C/POSIX scanner ใน WSL และสัญญา NDJSON
2. Windows Allocated API + bridge + SQLite + งานสแกนเบื้องหลัง/ยกเลิก
3. Tree/table โหลดทีละ 50 รายการ, error/partial, ปุ่มที่ทดสอบแล้ว และ offline assets
4. ผลทดสอบ/benchmark จากเครื่องเดโม รายงาน และสไลด์ 7 หน้า

ดูเจ้าของงานและวันปิดงานที่ [PROJECT_PLAN.md](PROJECT_PLAN.md) งานในรายการนี้ **ยังไม่ถือว่าเสร็จ** จนมีหลักฐานตามเกณฑ์รับงาน
