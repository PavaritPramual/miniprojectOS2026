# เมืองไฟล์ CoreSpace

เพิ่มวันที่ 12 ตุลาคม 2569 ตามคำขอให้ใช้เมืองจำลองจากไฟล์จริง แสดงคู่กับ tree ตาราง และกราฟแท่งเดิม

## สืบค้นก่อนออกแบบ

- [CodeCity — งานวิจัยต้นฉบับ](https://www.inf.usi.ch/faculty/lanza/PUBS/P/Wett2008a.pdf) ใช้อาคารและย่านแทนโครงสร้างซอฟต์แวร์ แนวคิดที่นำมาใช้คือรักษาความสัมพันธ์ของรายการในย่านเดียวกัน ไม่ได้นำตัวชี้วัดโค้ดมาใช้กับขนาดไฟล์
- [Treemapolis — repository ต้นฉบับ](https://github.com/smourier/Treemapolis) เป็นตัวอย่างการแสดงดิสก์ด้วยเมือง โฟลเดอร์เป็นแปลง ไฟล์เป็นอาคาร และเข้าโฟลเดอร์เพื่อสำรวจต่อได้ CoreSpace ใช้แนวคิดนี้บนเว็บ ไม่ใช้ระบบ DirectX หรือคัดลอกโค้ดของโครงการนั้น
- [D3 treemap — เอกสารทางการ](https://d3js.org/d3-hierarchy/treemap) อธิบายการแบ่งพื้นที่ตามค่าของข้อมูลและ squarified layout จึงใช้ D3 hierarchy 3.1.2 ที่เก็บในโปรเจกต์พร้อม ISC license
- [Semantic Zoom and Mini-Maps for Software Cities](https://arxiv.org/html/2510.00003v1) ศึกษาปัญหาการสำรวจเมืองข้อมูลขนาดใหญ่ งานนี้จึงแสดงรายละเอียดเป็นระดับและมีการเข้าโฟลเดอร์ ไม่พยายามส่งทั้งดิสก์เข้า browser ในครั้งเดียว
- [SVG polygon](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/polygon) และ [Pointer events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events) ใช้เป็นแนวทางสร้างรูปทรงและการลากด้วยเมาส์/สัมผัส

## เมืองหมายถึงอะไร

| สิ่งที่เห็น | ข้อมูลที่ใช้ |
| --- | --- |
| แปลง/ย่านโฟลเดอร์ | โฟลเดอร์จริงและยอดรวมที่ Python ส่งมา |
| อาคาร | ไฟล์จริง พื้นที่ฐานเทียบขนาดที่เลือก |
| ความสูง | ขนาดที่ย่อด้วย log เพื่อให้ไฟล์เล็กยังเห็น ไม่ใช่ความสูงต่อไบต์ |
| สี | ประเภทตามนามสกุล เช่น เอกสาร รูป วิดีโอ ไม่ได้อ่านเนื้อหาไฟล์เพื่อจำแนก |
| พื้นที่สีเทา | ขนาดที่ทราบ แต่ยังไม่ได้แสดงรายละเอียด หรือรวมรายการเกินจำนวนที่วาด |
| รายการใต้เมือง | ไฟล์ 0 ไบต์และค่าที่ไม่ทราบ ไม่มีพื้นที่สมมติให้สองกรณีนี้ |

เลือกใช้ Allocated หรือ Logical ได้ พื้นที่ไม่รวมยอดโฟลเดอร์ซ้ำกับยอดไฟล์ลูก ถนนและช่องว่างทำให้พื้นที่ที่มองเห็นเป็นการเทียบโดยประมาณ ตัวเลขจริงดูจากแผงรายการที่เลือกและตาราง

ใช้มุมมองเมืองแบบ isometric ที่สร้างด้วย SVG หรือเปลี่ยนเป็นแผนที่ได้ อาคารและแปลงทุกชิ้นอ้างอิงรายการไฟล์หรือพื้นที่รวมที่ระบุ

## ใช้เมืองทำอะไรได้

1. เลือกย่านหรืออาคารเพื่อดูชื่อ path และขนาดสองค่า
2. กดเข้าโฟลเดอร์ สำรวจต่อได้ทุกระดับที่สแกนพบ หรือกลับผ่าน breadcrumb
3. กดดูในตารางเพื่อไปยังรายการจริงและทำเครื่องหมายแถว
4. กดเปิดตำแหน่งเพื่อส่งคำสั่งไปยัง Windows Explorer ข้อความสำเร็จหมายถึงส่งคำสั่งได้ ไม่ได้ยืนยันว่าผู้ใช้เห็นหน้าต่างแล้ว
5. หมุน ขยาย ย่อ ลาก และคืนมุมมอง ปุ่มทุกตัวเปลี่ยนมุมมองจริง
6. หาชื่อและเลือกประเภทในข้อมูลของเมืองที่โหลดแล้ว ไม่มีการค้นทั้งดิสก์ที่ยังไม่สแกน
7. โหลดเพิ่มทีละ 50 รายการ และเลือก Logical/Allocated โดยใช้ค่าที่ได้รับจริง

ขนาดภาพจำกัดรายการที่มีข้อมูลแยก 250 รายการ ส่วนเกินรวมเป็นพื้นที่สีเทาโดยไม่ทำยอดหาย โฟลเดอร์ลูกที่มีข้อมูลโหลดไว้แสดงรายละเอียดได้สองระดับต่อภาพ เข้าโฟลเดอร์เพื่อดูระดับถัดไป รายการที่มีค่าศูนย์/ไม่ทราบยังเลือกได้ใต้เมือง

## สิ่งที่แก้จากการตรวจใช้งาน

- หน้าใช้งานจริงไม่แสดงลิงก์เข้าโหมดสมมติแล้ว โหมดทดสอบยังเปิดเองด้วย `?mock=1` และมีป้ายชัดเจน
- เพิ่มปุ่มเปิดผลล่าสุดของตำแหน่งที่กรอก ใช้ `/api/scans/latest` ที่มีอยู่แล้ว ไม่ต้องจำรหัสงาน
- เปิดลิงก์ `/?scan=<รหัสงาน>` เพื่อโหลดผลจริงที่บันทึกไว้ และเลือกไดรฟ์ให้ตรงกับ path ที่กรอกหรือเปิดจากประวัติ
- ตัดหัวข้อคำเกริ่นและป้าย path สำหรับผู้พัฒนา เปลี่ยนข้อความอ้าง CONTRACT/backend ในกรณีผิดพลาดเป็นคำที่ผู้ใช้เข้าใจ
- โหลดลูกของโฟลเดอร์ที่เพิ่งพบเมื่อสแกนจบ แก้กรณีสแกนเร็วแต่ root โหลดครั้งแรกก่อน C ส่งข้อมูล
- แสดงเหตุผลที่ข้ามลิงก์เป็นภาษาไทย และคงรหัสปัญหาสำหรับตรวจสอบ
- แก้ HTML ของ component เมืองให้มี closing tag จริง จึงไม่กลืนตารางกับกราฟเดิม

## วิธีตรวจซ้ำ

`node tools/file-city-check.cjs` ตรวจยอดรวม ไม่ซ้ำโฟลเดอร์กับไฟล์ zero/null ขนาดสองค่า การรวมรายการเกินจำนวนที่วาด และพิกัดทุกมุม

`node tools/file-city-uat.cjs` ใช้เซิร์ฟเวอร์จริงที่ตั้ง C ใน WSL แล้ว และ Playwright ในเครื่อง ต้องตั้งค่าเหล่านี้ก่อนรัน:

```powershell
$env:CORESPACE_UAT_URL = 'http://127.0.0.1:8080'
$env:CORESPACE_UAT_PATH = '<fixture 64 ไฟล์ที่สร้างด้วย -VariedSizes>'
$env:CORESPACE_UAT_CANCEL_PATH = '<fixture จำนวนมากสำหรับยกเลิก>'
$env:CORESPACE_UAT_ISSUES_PATH = '<fixture ที่มี -IncludeJunction>'
$env:CORESPACE_UAT_PROJECT_PATH = '<โฟลเดอร์เอกสารจริงของโปรเจกต์>'
$env:CORESPACE_BROWSER_CHANNEL = 'chrome'
node tools/file-city-uat.cjs
```

UAT ไม่ดักคำตอบ API และไม่เปลี่ยนไปใช้ mock เมื่อ C เรียกไม่ได้ ผลเก็บใน `output/playwright/file-city-uat/` ใช้ฐานข้อมูลทดสอบแยกจากงานส่วนตัวตามค่าตั้งเซิร์ฟเวอร์ ดูหลักฐานที่ส่งใน `docs/results/file-city-*`

ไม่มี benchmark และยังไม่อ้างว่าสแกนทั้งไดรฟ์จบหรือครอบคลุมทุกสิทธิ์ NTFS

ดู [ผล UAT และภาพจริง](results/FILE_CITY_UAT.md) พร้อมแยกหลักฐาน C จริงออกจากข้อมูล fixture ในชุดตรวจขอบเขต
