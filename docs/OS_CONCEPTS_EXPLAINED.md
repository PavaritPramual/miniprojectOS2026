# ความรู้จากวิชา OS ที่ใช้ในงานนี้

OS หรือระบบปฏิบัติการ เช่น Windows และ Linux เป็นผู้ดูแลไฟล์และอุปกรณ์ของเครื่อง โปรแกรมของเราขอข้อมูลจากระบบปฏิบัติการ แล้วจัดให้คนอ่านได้ง่ายผ่านหน้าเว็บ

คำศัพท์ในหน้านี้ใช้ช่วยอธิบายงานต่ออาจารย์ ให้เชื่อมกับโค้ดที่ทำจริงและผลที่ทดลองไว้

## อ่านไฟล์และโฟลเดอร์

โฟลเดอร์หนึ่งมีไฟล์และโฟลเดอร์ย่อย โปรแกรมต้องอ่านรายชื่อข้างใน แล้วเข้าไปอ่านโฟลเดอร์ย่อยต่อ วิธีนี้ทำให้สร้างภาพโฟลเดอร์แตกเป็นกิ่ง หรือที่เรียกว่า **tree** ได้

ข้อมูลที่อ่าน เช่น ชื่อ ชนิด และขนาด เรียกว่า **metadata** หรือข้อมูลเกี่ยวกับไฟล์ การรู้ขนาดไฟล์จึงไม่จำเป็นต้องเปิดอ่านเนื้อหาทั้งไฟล์

ส่วน C ตามแผนใช้คำสั่งตามมาตรฐาน **POSIX** ซึ่งกำหนดวิธีเรียกใช้ความสามารถของระบบแบบ Unix/Linux คำสั่งที่เกี่ยวข้องมีดังนี้:

| คำสั่งใน C | ทำอะไรในงานนี้ |
| --- | --- |
| `opendir()` | เปิดโฟลเดอร์เพื่อเตรียมอ่านรายการ |
| `readdir()` | อ่านรายการถัดไปในโฟลเดอร์ |
| `lstat()` | อ่านข้อมูลของรายการ เช่น ชนิดและขนาด โดยไม่ตามลิงก์ไปยังปลายทาง |
| `closedir()` | ปิดการอ่านโฟลเดอร์เมื่อใช้เสร็จ |

คำสั่งเหล่านี้เป็นส่วนติดต่อที่โปรแกรมใช้ผ่านไลบรารีของระบบ การเรียกหนึ่งครั้งไม่ได้แปลว่าจะตรงกับการเรียกเคอร์เนลหนึ่งครั้งเสมอ หากอธิบายเรื่อง system calls ให้แยกชื่อคำสั่งที่เขียนใน C ออกจากการทำงานภายในระบบ

## สิทธิ์เข้าถึงและการอ่านวน

บางโฟลเดอร์ต้องมีสิทธิ์พิเศษจึงจะอ่านได้ เมื่อเข้าไม่ได้ โปรแกรมควรแจ้งปัญหาและอ่านรายการอื่นต่อ ผลรวมจึงอาจเป็นเพียงส่วนที่อ่านได้

บางรายการเป็น **ลิงก์** คือชื่อที่ชี้ไปยังตำแหน่งอื่น ถ้าชี้กลับมาที่โฟลเดอร์เดิมแล้วโปรแกรมตามไปเรื่อย ๆ อาจทำให้ทำงานวนไม่จบ แผนนี้จึงข้ามการตามลิงก์และบอกผู้ใช้ว่าข้ามรายการใด

## ขนาดที่แสดงหมายถึงอะไร

| ชื่อบนเว็บ | ความหมาย |
| --- | --- |
| ขนาดเนื้อหาไฟล์ — Logical Size | จำนวนไบต์ของเนื้อหาไฟล์ตามข้อมูลที่ระบบรายงาน ส่วน C อ่านได้จาก `st_size` |
| พื้นที่ที่ไฟล์ใช้บนดิสก์ — Allocated Size | จำนวนไบต์ที่ Windows รายงานว่าไฟล์ใช้บนดิสก์ แผนใช้คำสั่ง `GetCompressedFileSizeW` อ่านค่านี้ |
| ขนาดรวมของโฟลเดอร์ | ผลบวกของไฟล์ข้างในที่โปรแกรมอ่านได้ |

ตัวอย่างเชิงอธิบาย: ไฟล์หนึ่งอาจมีเนื้อหาเล็ก แต่ใช้พื้นที่บนดิสก์มากกว่านั้น ขณะที่ไฟล์บีบอัดบางชนิดอาจใช้พื้นที่น้อยกว่าขนาดเนื้อหา ต้องอ่านค่าจริงก่อนบอกผลของไฟล์ใดไฟล์หนึ่ง

ยอดรวมที่โปรแกรมอ่านได้อาจไม่เท่าพื้นที่ใช้ทั้งหมดของไดรฟ์ เพราะมีไฟล์ที่เข้าไม่ถึง ข้อมูลที่ระบบใช้จัดการดิสก์ และไฟล์เดียวที่มีหลายชื่อให้เข้าถึง ตัวเลขที่ไม่ทราบควรแสดงว่า “ไม่ทราบ” แทนศูนย์

ต้นแบบมีสูตรประมาณพื้นที่และส่วนต่างที่เรียกว่า Slack Space สูตรนี้ใช้แทนผลวัดจริงไม่ได้ในทุกกรณี จึงไม่ควรนำตัวเลขจากสูตรไปอธิบายว่าเป็นพื้นที่จริงของไฟล์

## ความเร็วเกี่ยวกับอะไร

การอ่านข้อมูลไฟล์เป็นงานรับส่งข้อมูลกับระบบ หรือ **I/O** ถ้ามีไฟล์จำนวนมากก็มีรายการต้องอ่านมากขึ้น การเพิ่มจำนวนงานที่อ่านพร้อมกันไม่ได้รับประกันว่าจะเร็วขึ้นทุกเครื่อง

เวลารายงานผล ให้บอกว่าสแกนโฟลเดอร์ใด มีไฟล์เท่าไร และใช้กี่วินาที ถ้าจะเปรียบเทียบโปรแกรมสองแบบ ต้องใช้ชุดไฟล์เดียวกัน นอกจากนี้ให้ลองด้วยว่าหน้าเว็บยังกดและเลื่อนดูได้ระหว่างรอหรือไม่
