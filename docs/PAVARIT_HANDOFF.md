# เปิดและส่งต่อส่วนปวริศช์

ต่อ C ของศรัณย์จาก PR #3 กับ Python และเว็บจริงแล้ว ตรวจโฟลเดอร์บนไดรฟ์ D รวมชื่อไทยและ junction ได้ ทุกอย่างเปิดบน Windows เครื่องเดียว ส่วน C อยู่ใน Ubuntu ภายใน WSL ใช้ระบบ C → Python → เว็บแนวทางเดียว ไม่มีงาน benchmark เปรียบเทียบหรือวัดหน่วยความจำ ดู [ผลตรวจจริง](results/REAL_SCANNER_INTEGRATION.md)

## 1. เปิดโปรแกรม

เปิด PowerShell ที่โฟลเดอร์โปรเจกต์:

```powershell
.\tools\start.ps1
```

หากเครื่องไม่พบ Python ให้ใช้ตำแหน่งที่ติดตั้งจริง ตัวอย่างด้านล่างเป็นตำแหน่งสมมติ ให้เปลี่ยนก่อนใช้:

```powershell
.\tools\start.ps1 -PythonPath 'C:\Python312\python.exe'
```

เพิ่ม `-CheckOnly` เพื่อเช็กการตั้งค่าโดยยังไม่เปิดเซิร์ฟเวอร์ เปิดโปรแกรมแล้วใช้ `http://127.0.0.1:8080` ปิดด้วย Ctrl+C หน้าเว็บใหม่เรียก API `/api/scans` และเก็บ Vue/CSS ในโปรเจกต์แล้ว

เมื่อต่อโปรแกรม C แล้ว:

ใน Ubuntu เข้าโฟลเดอร์โปรเจกต์ รัน `make -C scanner` แล้ว `make -C scanner install` จากนั้นใช้ `readlink -f ~/.local/bin/diskviz-scan` ดูตำแหน่งเต็มของโปรแกรม เพื่อใส่ในคำสั่งเปิดด้านล่าง ไม่ต้องใช้ตำแหน่งเดียวกับเครื่องคนเขียน

```powershell
.\tools\start.ps1 -PythonPath 'C:\Python312\python.exe' `
  -ScannerWslPath '/home/student/.local/bin/diskviz-scan' -Distro Ubuntu
```

ตำแหน่ง Python และ C ในตัวอย่างต้องเปลี่ยนให้ตรงเครื่อง โปรแกรม C ต้องเปิดได้ด้วย `--root <path> --ndjson` ตาม CONTRACT ถ้าไม่ได้ตั้ง C ไว้ ปุ่ม Scan และ API สแกนจริงจะแจ้งข้อผิดพลาด หน้าเว็บยังเปิดได้และลองข้อมูลตัวอย่างตามข้อ 2 ได้

## 2. ลองข้อมูลตัวอย่างเมื่อต้องการตรวจแยกส่วน

ข้อมูลตัวอย่างเลือกเองผ่าน API หน้าเว็บยังไม่มีปุ่มเลือก Python sample เปิดเซิร์ฟเวอร์ด้วยฐานข้อมูลทดสอบแยกก่อน:

```powershell
.\tools\start.ps1 -PythonPath 'C:\Python312\python.exe' `
  -DatabasePath '.\fixtures\generated\sample-check.sqlite3'
```

เปลี่ยนตำแหน่ง Python ให้ตรงเครื่อง จาก PowerShell อีกหน้าต่างเริ่มข้อมูลตัวอย่าง:

```powershell
$job = Invoke-RestMethod 'http://127.0.0.1:8080/api/scans' -Method Post `
  -ContentType 'application/json' -Body '{"path":"D:\\demo","source":"sample"}'
$scanId = $job.id
Invoke-RestMethod "http://127.0.0.1:8080/api/scans/$scanId"
Invoke-RestMethod "http://127.0.0.1:8080/api/scans/$scanId/children?parent=&offset=0&limit=50"
Invoke-RestMethod "http://127.0.0.1:8080/api/scans/$scanId/children?parent=many&offset=0&limit=50"
Invoke-RestMethod "http://127.0.0.1:8080/api/scans/$scanId/children?parent=many&offset=50&limit=50"
```

ช่วงเริ่มต้น root ตอบได้แต่ขนาดยังเป็น `null` และรายการยังว่าง ให้ถามสถานะและโหลดใหม่เมื่อจบ โฟลเดอร์ย่อยที่ยังไม่ได้รับข้อมูลอาจตอบ `404` ข้อมูลตัวอย่างมี 64 ไฟล์/13 โฟลเดอร์ `many` มี 60 ลูก แบ่งเป็น 50 + 10 ค่าพื้นที่และเวลาในไฟล์ตัวอย่างเป็นค่าจำลอง

เมื่อสถานะเป็น `completed` เปิดหน้าเว็บ กาง “เปิดผลสแกนที่เตรียมไว้” วางค่า `$scanId` ใน “รหัสงานสแกน” แล้วกด “เปิดผลด้วยรหัส” ตรวจยอด root, โฟลเดอร์ `many`, `empty`, `zero.bin` และ `large.bin` ผลนี้ยังเป็นข้อมูลสมมติ แม้หน้าเว็บจะอยู่ที่ URL ปกติ ตรวจ `isSample: true` จาก API และระบุว่าเป็นข้อมูลทดสอบเมื่อใช้ภาพหรือผลในรายงาน

`/?mock=1` ใช้ตัวจำลองใน browser สำหรับลอง UI เท่านั้น ไม่ผ่านส่วนรับข้อมูลของ Python การตรวจ Python ในรอบนี้ใช้ API ตามด้านบน

**ข้อความส่งให้ธีรเมธครั้งเดียว:**

> API ใหม่พร้อมลองด้วย `source: "sample"` แล้ว ใช้ `/api/scans` เริ่มงาน ถามสถานะทุก 2 วินาที และขอ `/children` ครั้งละ 50 รายการ มี `folder` สำหรับขนาดของโฟลเดอร์ที่เลือก และ `/issues` สำหรับดูปัญหา ระหว่างสแกนรายการเรียงตามลำดับรับ เมื่อจบให้ล้างหน้าที่เคยโหลดแล้วโหลดใหม่เพราะจะเรียงตามพื้นที่ ใช้ `null` แสดงกำลังคำนวณหรือไม่ทราบตามสถานะ และเช็ก `response.ok` ทุกปุ่ม ผลจริงเดิมเปิดกลับได้ผ่าน `/api/scans/latest?path=...` รายละเอียดและตัวอย่างอยู่ใน CONTRACT

ข้อความนี้เตรียมไว้ให้ส่งเอง ยังไม่ได้ส่งถึงสมาชิก

## 3. รันชุดตรวจรับ

ใช้ Windows Python ตัวเดียวกับที่เปิดเซิร์ฟเวอร์ หากคำสั่ง `python` ใช้ไม่ได้ ให้แทนด้วย `& 'ตำแหน่งเต็มของ python.exe'`

```powershell
python tools/run_checks.py
```

ตรวจการเชื่อมและยกเลิก Ubuntu ด้วย เพิ่ม `--wsl` ต้องมี Ubuntu, Python 3 ใน WSL และชุดโฟลเดอร์ทดสอบ:

```powershell
# สร้างเฉพาะครั้งแรก ถ้ามี fixtures/generated/demo แล้วไม่ต้องรันซ้ำ
.\tools\prepare_demo_fixture.ps1
python tools/run_checks.py --wsl
```

ผลตรวจเก็บใน `docs/results/backend-tests.txt` ฐานข้อมูล/ไฟล์ทดสอบแยกไว้ในโฟลเดอร์ชั่วคราวใต้ `fixtures/generated` แล้วลบหลังตรวจเสร็จ การเปิด Explorer ถูกจำลอง ส่วนการส่งและหยุดโปรแกรมใน Ubuntu เป็นการเรียกจริง

`tests/wsl_mock.py` เป็นโปรแกรมสำหรับทดสอบการส่งข้อมูลและการหยุดเท่านั้น ไม่ใช่โปรแกรม C ของกลุ่ม ห้ามใช้ผลนี้อ้างว่างาน C เสร็จหรือเร็ว

หากแก้ข้อมูลตัวอย่างให้สร้างสองไฟล์ร่วมกันแล้วรันทดสอบ:

```powershell
python tools/generate_examples.py
python tools/run_checks.py
```

## 4. ตรวจการรวมระบบด้วย C จริง

ขั้นตอนนี้ตรวจผ่านแล้วบนเครื่องกลุ่มวันที่ 6 ต.ค. ดู [ผลและข้อจำกัด](results/REAL_SCANNER_INTEGRATION.md) ใช้รายการด้านล่างเมื่อเพื่อนเปิดบนเครื่องอื่นหรือก่อนนำเสนอ

ตรวจอัตโนมัติด้วย `python tools/run_checks.py --wsl --real-scanner-wsl-path '/home/ชื่อผู้ใช้/.local/bin/diskviz-scan' --output docs/results/real-scanner-tests.txt` เพิ่ม `--drive 'D:\'` เมื่อต้องการตรวจยกเลิกสแกนไดรฟ์จริง ชุดนี้ใช้ฐานข้อมูลชั่วคราว ไม่ทับผลใช้งาน

1. ตั้งตำแหน่ง C ด้วยคำสั่งเปิดโปรแกรมในข้อ 1
2. เริ่มสแกน fixture จริงโดยไม่ใส่ `source: "sample"` ตรวจ 64 ไฟล์/13 โฟลเดอร์ และหน้ารายการ 50 + 10
3. ให้ธีรเมธลองปุ่ม Scan กาง tree แสดงเพิ่มเติม ดูปัญหา ยกเลิก และ Reveal
4. ลองยกเลิกระหว่างอ่านจริงและเริ่มงานใหม่ ตรวจว่า C หยุดจริงด้วย ไม่ใช้ผลโปรแกรมจำลองแทน
5. เทียบขนาดไฟล์กับคุณสมบัติไฟล์บน Windows เก็บค่าหรือภาพที่ตรวจได้
6. ลองทั้งไดรฟ์พร้อมดูว่าเว็บยังตอบสนอง จดจำนวน ข้อผิดพลาด และผลการยกเลิกตามจริง ผลทั้งไดรฟ์เปิดกลับได้ผ่าน `/latest` ไม่มีการวัดเปรียบเทียบกับต้นแบบ

## 5. หลักฐานสำหรับรายงาน

บันทึกว่าทดลองอะไร ผ่านหรือไม่ผ่าน จำนวนรายการ ขนาดที่ตรวจ และข้อจำกัด เก็บภาพเมื่อทดสอบด้วยไฟล์จริงแล้ว อธิบายสถาปัตยกรรมและคำสั่ง OS ที่ใช้ ไม่ต้องเก็บความเร็ว หน่วยความจำ หรือรันเปรียบเทียบสามรอบ เวลาที่หน้าเว็บแสดงเป็นสถานะของงาน ไม่ใช่ผล benchmark

ผลทดสอบวันที่ 4 ต.ค. เก็บไว้ที่ [ประวัติผลทดสอบ](results/archive/backend-tests-2026-10-04.txt) รวมข้อทดสอบเครื่องมือ benchmark ที่ถอดออกแล้ว ให้ใช้ [ผลล่าสุด](results/backend-tests.txt) สำหรับสถานะปัจจุบัน

## สิ่งที่ยังต้องรับจากเพื่อน

- **ศรัณย์:** source/binary C ที่อ่านไฟล์จริงและส่งข้อมูลตาม CONTRACT
- **ธีรเมธ:** เว็บใหม่ merge แล้ว เหลือการตรวจปุ่มกับข้อมูลจริง และงานเชื่อมเปิดผลล่าสุด/เลือก Python sample ตามเอกสาร UI
- **ปวริศช์หลังรวม:** หลักฐานขนาด สแกนทั้งไดรฟ์ การยกเลิก และผลทดสอบ C จริง เติมในบันทึกรายงาน
