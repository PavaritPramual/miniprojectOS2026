# เปิดและส่งต่อส่วนปวริศช์

ส่วน Python พร้อมให้เพื่อนลองเชื่อมด้วยข้อมูลตัวอย่างได้ โปรแกรม C ของศรัณย์และหน้าเว็บใหม่ของธีรเมธยังต้องนำมาต่อภายหลัง ทุกอย่างเปิดบน Windows เครื่องเดียว ส่วน C อยู่ใน Ubuntu ภายใน WSL

## 1. เปิดโปรแกรม

เปิด PowerShell ที่โฟลเดอร์โปรเจกต์:

```powershell
.\tools\start.ps1
```

หากเครื่องไม่พบ Python ให้ใช้ตำแหน่งที่ติดตั้งจริง ตัวอย่างด้านล่างเป็นตำแหน่งสมมติ ให้เปลี่ยนก่อนใช้:

```powershell
.\tools\start.ps1 -PythonPath 'C:\Python312\python.exe'
```

เพิ่ม `-CheckOnly` เพื่อเช็กการตั้งค่าโดยยังไม่เปิดเซิร์ฟเวอร์ เปิดโปรแกรมแล้วใช้ `http://127.0.0.1:8080` ปิดด้วย Ctrl+C หน้าเว็บที่มีอยู่ตอนนี้ยังเรียก API ของต้นแบบ

เมื่อต่อโปรแกรม C แล้ว:

```powershell
.\tools\start.ps1 -PythonPath 'C:\Python312\python.exe' `
  -ScannerWslPath '/home/student/corespace/diskviz-scan' -Distro Ubuntu
```

ตำแหน่ง Python และ C ในตัวอย่างต้องเปลี่ยนให้ตรงเครื่อง โปรแกรม C ต้องเปิดได้ด้วย `--root <path> --ndjson` ตาม CONTRACT ถ้าไม่ได้ตั้ง C ไว้ API สแกนจริงจะแจ้งข้อผิดพลาด ส่วนเว็บต้นแบบและข้อมูลตัวอย่างยังใช้ลองได้

## 2. ธีรเมธเริ่มต่อเว็บได้เลย

ไม่ต้องรอ C เปิดเซิร์ฟเวอร์ก่อน จาก PowerShell อีกหน้าต่างเริ่มข้อมูลตัวอย่าง:

```powershell
$job = Invoke-RestMethod 'http://127.0.0.1:8080/api/scans' -Method Post `
  -ContentType 'application/json' -Body '{"path":"D:\\demo","source":"sample"}'
$scanId = $job.id
Invoke-RestMethod "http://127.0.0.1:8080/api/scans/$scanId"
Invoke-RestMethod "http://127.0.0.1:8080/api/scans/$scanId/children?parent=&offset=0&limit=50"
Invoke-RestMethod "http://127.0.0.1:8080/api/scans/$scanId/children?parent=many&offset=0&limit=50"
Invoke-RestMethod "http://127.0.0.1:8080/api/scans/$scanId/children?parent=many&offset=50&limit=50"
```

ถ้า root ยังไม่เข้าฐานข้อมูลอาจได้ `404` ช่วงเริ่มต้น ให้ถามสถานะและลองอีกครั้ง ข้อมูลตัวอย่างมี 64 ไฟล์/13 โฟลเดอร์ `many` มี 60 ลูก แบ่งเป็น 50 + 10 ค่าพื้นที่และเวลาในไฟล์ตัวอย่างเป็นค่าจำลอง

**ข้อความส่งให้ธีรเมธครั้งเดียว:**

> API ใหม่พร้อมลองด้วย `source: "sample"` แล้ว ใช้ `/api/scans` เริ่มงาน ถามสถานะทุก 2 วินาที และขอ `/children` ครั้งละ 50 รายการ มี `folder` สำหรับขนาดของโฟลเดอร์ที่เลือก และ `/issues` สำหรับดูปัญหา ระหว่างสแกนรายการเรียงตามลำดับรับ เมื่อจบให้ล้างหน้าที่เคยโหลดแล้วโหลดใหม่เพราะจะเรียงตามพื้นที่ ใช้ `null` แสดงกำลังคำนวณหรือไม่ทราบตามสถานะ และเช็ก `response.ok` ทุกปุ่ม ผลจริงเดิมเปิดกลับได้ผ่าน `/api/scans/latest?path=...` รายละเอียดและตัวอย่างอยู่ใน CONTRACT

ข้อความนี้เตรียมไว้ให้ส่งเอง ยังไม่ได้ส่งถึงสมาชิก

## 3. รันชุดตรวจรับ

ใช้ Windows Python ตัวเดียวกับที่เปิดเซิร์ฟเวอร์ หากคำสั่ง `python` ใช้ไม่ได้ ให้แทนด้วย `& 'ตำแหน่งเต็มของ python.exe'`

```powershell
python tools/run_checks.py
```

ตรวจการเชื่อมและยกเลิก Ubuntu ด้วย เพิ่ม `--wsl` ต้องมี Ubuntu, Python 3 และ GNU time ใน WSL และชุดโฟลเดอร์ทดสอบ:

```powershell
# สร้างเฉพาะครั้งแรก ถ้ามี fixtures/generated/demo แล้วไม่ต้องรันซ้ำ
.\tools\prepare_demo_fixture.ps1
python tools/run_checks.py --wsl
```

ผลตรวจเก็บใน `docs/results/backend-tests.txt` ฐานข้อมูล/ไฟล์ทดสอบแยกไว้ในโฟลเดอร์ชั่วคราวใต้ `fixtures/generated` แล้วลบหลังตรวจเสร็จ การเปิด Explorer ถูกจำลอง ส่วนการส่งและหยุดโปรแกรมใน Ubuntu เป็นการเรียกจริง

`tests/wsl_mock.py` เป็นโปรแกรมสำหรับทดสอบการส่งข้อมูลและการหยุดเท่านั้น ไม่ใช่โปรแกรม C ของกลุ่ม ห้ามใช้ผลนี้อ้างว่างาน C เสร็จหรือเร็ว

หากแก้ข้อมูลตัวอย่างให้สร้างสองไฟล์ร่วมกันแล้วรันทดสอบ:

```powershell
python tools/generate_examples.py
python tools/run_checks.py
```

## 4. เมื่อศรัณย์ส่งโปรแกรม C

1. ตั้งตำแหน่ง C ด้วยคำสั่งเปิดโปรแกรมในข้อ 1
2. เริ่มสแกน fixture จริงโดยไม่ใส่ `source: "sample"` ตรวจ 64 ไฟล์/13 โฟลเดอร์ และหน้ารายการ 50 + 10
3. ให้ธีรเมธลองปุ่ม Scan กาง tree แสดงเพิ่มเติม ดูปัญหา ยกเลิก และ Reveal
4. ลองยกเลิกระหว่างอ่านจริงและเริ่มงานใหม่ ตรวจว่า C หยุดจริงด้วย ไม่ใช้ผลโปรแกรมจำลองแทน
5. เทียบขนาดไฟล์กับคุณสมบัติไฟล์บน Windows เก็บค่าหรือภาพที่ตรวจได้
6. ใช้เครื่องมือด้านล่างเก็บตัวเลขต้นแบบ/รุ่นใหม่ แล้วลองทั้งไดรฟ์พร้อมดูว่าเว็บยังตอบสนอง ผลทั้งไดรฟ์เปิดกลับได้ผ่าน `/latest`

## 5. เก็บเวลาและหน่วยความจำหลังต่อ C

```powershell
python tools/benchmark_backend.py --path 'D:\demo' `
  --scanner '/home/student/corespace/diskviz-scan' --runs 3 `
  --output docs/results/benchmark-real.json
```

เปลี่ยน path ให้ตรงชุดที่จะใช้จริง เครื่องมือเปิด Python ใหม่ทุกรอบ สลับต้นแบบกับรุ่นใหม่ ใช้โฟลเดอร์เดียวกันอย่างละ 3 รอบ เก็บข้อมูลทุกครั้งและค่ากลาง:

- เวลาเริ่มตอบของส่วน backend และเวลาถึงข้อมูลแรก เวลาอ่านจบ จำนวนไฟล์/โฟลเดอร์ และไฟล์ต่อวินาที
- หน่วยความจำสูงสุดของ Python จาก Windows และของ C จาก GNU time แยกกัน
- สถานะและจำนวนปัญหา ไม่สลับเป็นข้อมูลตัวอย่างเมื่อ C ใช้ไม่ได้

เวลาเริ่มตอบนี้วัดส่วนเรียก backend ไม่รวมเครือข่ายหรือการวาดเว็บ ต้องลองการตอบสนองของหน้าเว็บอีกครั้งตอนรวมงาน ไม่มีการล้าง cache ของดิสก์ อธิบายเงื่อนไขนี้ในรายงาน รุ่นใหม่รวมการวัดพื้นที่และเขียน SQLite จึงทำงานต่างจากต้นแบบ

ใช้ `--test-only` เฉพาะตอนตรวจเครื่องมือด้วยโปรแกรมจำลอง ผลจะติดป้าย `testOnly: true` ห้ามนำไปอ้างเป็น benchmark ของ C หากจำนวนไฟล์ต่างกันหรือผลบางส่วนต้องตรวจสาเหตุก่อนสรุปว่าเร็วกว่า

## สิ่งที่ยังต้องรับจากเพื่อน

- **ศรัณย์:** source/binary C ที่อ่านไฟล์จริงและส่งข้อมูลตาม CONTRACT
- **ธีรเมธ:** เว็บที่ใช้ API ใหม่และผลตรวจปุ่มจริง
- **ปวริศช์หลังรวม:** หลักฐานขนาด เวลา หน่วยความจำ สแกนทั้งไดรฟ์ และผลทดสอบ C จริง เติมในบันทึกรายงาน
