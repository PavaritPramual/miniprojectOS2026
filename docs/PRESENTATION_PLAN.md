## 2. ลำดับเดโมและแผนสำรอง

1. ก่อนเข้าห้อง: ตรวจ `wsl.exe`, binary C, Python server, browser offline assets, ไดรฟ์/โฟลเดอร์ fixture และผลสแกนทั้งไดรฟ์ที่ทำไว้ก่อน ตรวจวันที่ของผล ไม่อ้างว่าเป็นผลสด
2. เปิดเว็บบน Windows เลือกโฟลเดอร์ย่อยที่มีไฟล์ไม่มากและ path ภาษาไทยอย่างน้อยหนึ่งรายการ กด Scan ให้เห็นสถานะและผลรวมที่จบในช่วงเดโม
3. กาง tree ถึงชั้นที่ 7–8 และเปิดโฟลเดอร์ที่มีลูกเกิน 50 รายการ กด “แสดงเพิ่มเติม” เพื่อพิสูจน์ว่าไม่ตัดรายการเงียบ
4. แสดง Logical/Allocated ของไฟล์ที่ตรวจเทียบไว้ และยกตัวอย่าง partial/error เฉพาะเมื่อทดสอบไว้จริง
5. เปิดผลสแกนทั้งไดรฟ์ที่เตรียมไว้ บอกเวลาสแกนจริงและจำนวนรายการที่อ่านได้ กด Reveal เฉพาะเมื่อผ่านการทดสอบบนเครื่องนั้น

ถ้า WSL หรือเครือข่ายเครื่องนำเสนอมีปัญหา ให้ใช้ภาพหน้าจอ/วิดีโอ **ที่ระบุว่าเป็นการบันทึกการรันก่อนหน้า** แทนเดโมสด และอธิบายฟีเจอร์ที่ยังไม่ได้พิสูจน์ตามจริง ห้ามนำภาพต้นแบบ Python/Win32 มาอ้างว่าเป็นผลจาก C/POSIX

## 3. รายงานฉบับสุดท้าย

ปวริศช์ประกอบรายงานหลัก ศรัณย์ตรวจส่วน C/POSIX และธีรเมธตรวจส่วน UI/ภาพประกอบ รายงานควรมีหัวข้อเรียงดังนี้:

1. ปัญหา วัตถุประสงค์ ขอบเขต และสมาชิก/หน้าที่
2. ความรู้ OS จาก syllabus: system calls, file metadata, directory traversal, I/O และเหตุผลที่ใช้ C/POSIX ใน WSL
3. สถาปัตยกรรมและ data flow รวมสัญญา NDJSON/API และสาเหตุที่เว็บใช้ Python เป็นตัวเชื่อม
4. ความหมาย Logical/Allocated แหล่งข้อมูล วิธีรวมโฟลเดอร์ และเหตุผลที่ผลรวมอาจไม่เท่าพื้นที่ใช้ทั้งไดรฟ์
5. ฟีเจอร์ที่รันได้จริงพร้อมภาพจากเวอร์ชันส่งงาน ไม่คัดคำกล่าวอ้างจาก HANDOFF ต้นแบบโดยไม่ตรวจ
6. วิธีทดสอบและผลจริง: fixture, ปุ่ม, error/cancel, benchmark, เครื่อง/ไดรฟ์ที่ใช้และวันที่วัด
7. ข้อจำกัด ความเสี่ยงที่ยังเหลือ และงานต่อในอนาคต
