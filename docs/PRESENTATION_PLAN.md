# แผนนำเสนอ CoreSpace — เน้นเนื้อหา OS

อัปเดต 12 ตุลาคม 2569 สำหรับการอัดคลิป ใช้ skill `presentation-design` และ `Presentations`: หนึ่งประเด็นต่อสไลด์ ตั้งหัวข้อเป็นข้อสรุป และใช้ภาพ โค้ด หรือผลจริงสนับสนุน รายละเอียดให้พูดประกอบแทนการใส่ย่อหน้าเต็มบนสไลด์

รูปแบบล่าสุดเป็น **อัดคลิปประมาณ 8 นาที** บรรยายทั้งสามคน ใช้ Canva Presentation 9 หน้า ขนาด 16:9 พร้อมช่วงบันทึกหน้าจอเดโมจริง 2 นาที ไม่ระบุกำหนดส่งใหม่จนกว่าอาจารย์จะแจ้ง

## ใจความหลัก

**CoreSpace ใช้บริการของระบบปฏิบัติการอ่านข้อมูลไฟล์ แล้วส่งข้อมูลระหว่างโปรแกรมเพื่อแสดงการใช้พื้นที่**

ผู้ฟังคืออาจารย์และเพื่อนในวิชา OS ต้องเห็นความเชื่อมโยงระหว่างแนวคิดที่เรียน โค้ดที่ใช้จริง และผลที่เดโม ไม่เน้นหน้าตาเว็บ ไม่เพิ่มเนื้อหา CPU scheduling, deadlock หรือ virtual memory ที่ไม่ได้ใช้ในงาน และไม่ทำ benchmark

## วิธีทำภาพและเลือกหลักฐาน

- ใช้ภาพผลจริงจาก [ผลการรวมระบบ](results/REAL_SCANNER_INTEGRATION.md) และเปลี่ยนภาพ mock ในสไลด์เดิมก่อนส่ง
- หน้า POSIX โชว์เฉพาะโค้ดที่อธิบายได้ ไม่วางทั้งไฟล์ แยกชื่อฟังก์ชันที่เขียนใน C ออกจาก syscall ภายใน ห้ามอ้างว่า trace แล้วถ้ายังไม่ได้ทำ
- หน้า process ใช้กล่องสามส่วนและลูกศร แยก HTTP ระหว่างเว็บกับ Python ออกจาก pipe ระหว่าง Python กับ C บอกว่า WSL อยู่ใน Windows เครื่องเดียว
- หน้า sizes ใช้ค่าที่วัดจริง ทั้งสองขนาดเท่ากันใน fixture นี้ได้ ไม่แต่งผลให้ต่างกัน และไม่เรียกผลต่างว่า Slack เสมอ
- ใช้ตัวอักษรเนื้อหาอย่างน้อยประมาณ 24 pt หัวข้อ 32 pt ขึ้นไป สี 3–5 สี ภาพต้องอ่านได้จากท้ายห้อง เก็บรายละเอียด API และข้อสอบซ้อมตอบในบทพูด
- ใช้ศัพท์อังกฤษคู่คำอธิบายไทยเมื่อจำเป็น ไม่อ่านทุกคำบนสไลด์

## ไฟล์ส่งสำหรับรูปแบบอัดคลิป

อาจารย์เปลี่ยนเป็นอัดคลิปตามที่ผู้ใช้แจ้งล่าสุด รายการส่งเดิมคือ demo, presentation และรายงานถ้ามี ให้เตรียมชุดนี้พร้อมคลิป แต่ยังไม่มีข้อมูลกำหนดส่งหรือช่องทางส่งใหม่ในบทสนทนา

- **Presentation:** Canva ฉบับ 9 หน้าที่แก้ข้อความและแผนภาพได้ พร้อมลิงก์แก้ไข ส่งออก PDF/PPTX เมื่อต้องใช้ไฟล์ส่ง ไม่ใช้ภาพแบนแทนต้นฉบับ Canva
- **คลิป:** MP4 แนวนอน 16:9 ประมาณ 8 นาที มีเสียงครบสามคนและเดโมจริง 2 นาที ตรวจภาพ เสียง และลำดับก่อนส่ง
- **Demo:** เตรียม ZIP โค้ด C/Python/เว็บ README และเครื่องมือสร้าง fixture ไม่รวม `.git`, ฐานข้อมูลส่วนตัว หรือไฟล์ทั้งไดรฟ์ เตรียมวิดีโอเดโมจริงสำรอง เพราะข้อความยังไม่ได้ระบุชัดว่าไฟล์ demo หมายถึงโปรแกรมหรือวิดีโอ
- **รายงานถ้ามี:** รวมเป้าหมาย สถาปัตยกรรม เนื้อหา OS ที่ใช้ ขนาดสองค่า ผลจริง ข้อจำกัด และหน้าที่สมาชิก ไม่ต้องสร้างรายงานยาวหรือ benchmark เพิ่มเพื่อให้ครบ

จัดไฟล์ที่จะส่งไว้ล่วงหน้าและเปิดตรวจทั้งต้นคลิป กลางคลิป และท้ายคลิป ข้อความอาจารย์ล่าสุดใช้กำหนดรูปแบบ ส่วน [syllabus](../../LectureDoc/Operating_Systems_and_System_Calls_Syllabus.docx.pdf) ใช้อ้างอิงเนื้อหาวิชาและ C/POSIX
