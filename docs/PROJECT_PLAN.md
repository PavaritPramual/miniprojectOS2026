## 2. งานรายคนและขอบเขตส่งมอบ

### นายศรัณย์ พาพรชัย — C/POSIX scanner

**รับผิดชอบ:** โปรแกรม C, การเดิน directory, error/skip records, การกันลูป และ build บน WSL ตามสัญญาใน SPEC<br>
**ไม่รับผิดชอบ:** สูตรจำลอง NTFS, หน้าเว็บ, การเปิด Explorer

- ส่ง CLI ที่รับ root path แล้วปล่อย NDJSON แบบ streaming; ไม่โหลดผลทั้งไดรฟ์ไว้ใน RAM ก่อนส่ง
- ใช้ POSIX API จริงและเช็ก return/errno; ไม่ตาม symbolic link, ตรวจรายการที่เข้าถึงไม่ได้ และส่ง `done.complete` ให้ตรงผล
- ทดลอง junction/reparse point บน `/mnt/c` จริง ถ้าพบว่าป้องกันวงวนไม่ได้ ต้องหยุดเปิด full-drive mode และรายงานข้อจำกัดให้ทีมก่อน 5 ต.ค.
- ทดสอบ fixture ทุกกรณี, การยกเลิก process และ build ใหม่จาก checkout สะอาด

**รับงานเมื่อ:** record ครบ schema, นับรายการ/ข้อผิดพลาดได้, path ไม่หลุด root, ไม่วนซ้ำ, สแกน fixture ลึก 8 ชั้นได้; ปวริศช์ลองรับ NDJSON จริงหนึ่งครั้ง

### นายปวริศช์ ประมวล — bridge, ตัวเลข, benchmark และรายงาน

**รับผิดชอบ:** Python server บน Windows, เปิด C scanner ผ่าน WSL, ตรวจ NDJSON, Windows Allocated API, SQLite scan cache, API งานเบื้องหลัง, ผลทดสอบตัวเลข และร่างรายงาน<br>
**ไม่รับผิดชอบ:** วาด tree หรือเพิ่มฟีเจอร์ UI นอกสเปก

- แปลง Windows path ครั้งเดียวต่อ scan; ประกอบ relative path ของแต่ละ record อย่างปลอดภัย ไม่ใช้ shell string จากผู้ใช้
- วัด Allocated ของ regular file ด้วย `GetCompressedFileSizeW`; `null`/partial เมื่อวัดไม่ได้ ไม่ใช้ `calculate_physical_and_slack()` เป็นผลจริง
- ทำ job status, cancellation, SQLite แบบ batch/pagination และ bind server กับ localhost
- ทำ benchmark บน fixture เดียวกันระหว่างต้นแบบกับระบบใหม่ และวัด full-drive run บนเครื่องเดโม; เก็บเวลา จำนวนรายการ/วินาที peak memory พร้อมวิธีวัด
- ร่างรายงานตาม syllabus: เป้าหมาย, สถาปัตยกรรม, POSIX calls, Windows API, ผลทดสอบ, ข้อจำกัด, หน้าที่สมาชิก ให้เพื่อนตรวจส่วนของตน

**รับงานเมื่อ:** API ตาม SPEC ใช้ได้, ขนาดตัวอย่างตรงแหล่งวัด, งานหยุด/ยกเลิกไม่ค้าง, ข้อผิดพลาดไม่ถูกแสดงเป็นศูนย์; ศรัณย์ลองสั่งงาน WSL และธีรเมธลองต่อ API จริง

### นายธีรเมธ สายคำ — เว็บ tree, การใช้งาน และเดโม

**รับผิดชอบ:** หน้าเว็บ, tree/tables, สถานะงาน, ปุ่ม, ความพร้อมใช้งาน offline, สไลด์และการสาธิต<br>
**ไม่รับผิดชอบ:** การคำนวณ Allocated หรือโค้ด C scanner

- ใช้ fixture/API ตาม SPEC เพื่อแสดง tree โฟลเดอร์และตารางไฟล์; เปิดเริ่มต้น 2 ชั้น, โหลด 50 รายการ/หน้า, กางได้เกิน 6 ชั้นโดยไม่ซ่อนเงียบ
- แสดง queued/running/completed/partial/cancelled/failed; ปุ่ม Scan, Cancel, Reveal, กาง/พับ, แสดงเพิ่มเติมต้องแจ้งผลหรือข้อผิดพลาด
- เปลี่ยนการโหลด Vue/CSS runtime จาก CDN เป็นไฟล์เวอร์ชันตรึงใน `static/` ก่อนเดโม เพื่อให้หน้าเว็บเปิดได้เมื่อไม่มีอินเทอร์เน็ต
- บันทึกการทดสอบปุ่มทุกปุ่มพร้อมภาพหน้าจอ; ทำสไลด์ 7 หน้าและสคริปต์เดโมตาม [PRESENTATION_PLAN.md](PRESENTATION_PLAN.md)

**รับงานเมื่อ:** fixture 60 ลูก/8 ชั้นเข้าถึงได้ครบ, UI ตอบสนองระหว่าง full-drive scan, ปุ่มทำงานตามผล API และเปิดหน้าเว็บ offline ได้; ปวริศช์ลองกด Scan/Cancel/Reveal จากเว็บจริง
