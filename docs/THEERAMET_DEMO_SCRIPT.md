## ซ้อมตอบคำถามสั้น ๆ ของธีรเมธ

**เว็บเรียก C โดยตรงหรือไม่?** ไม่โดยตรง เว็บส่ง HTTP ให้ Python แล้ว Python เปิด process C ผ่าน WSL ตามแผนกลุ่ม

**ทำไมต้องมี scan id?** เพื่อให้ status, children, cancel และ reveal อ้างถึงงานเดียวกัน และเปิดผลที่สแกนไว้ก่อนกลับมาดูได้

**ทำไมใช้ 50 รายการ?** เป็นขนาดหน้าที่ทีมตกลงเพื่อลดข้อมูลต่อ request และจำนวนแถวที่วาดครั้งแรก ไม่ใช่ข้อบังคับของ OS

**ทำไมหน้าเว็บไม่ค้าง?** fetch รอคำตอบแบบ asynchronous; backend ต้องทำ scan เป็นงานเบื้องหลังด้วย UI โหลดเฉพาะหน้าที่ต้องดู

**ทำไมต้องโหลดใหม่เมื่อสแกนจบ?** ขณะสแกนรายการเพิ่มและขนาดรวมเปลี่ยน ลำดับสุดท้ายอาจเปลี่ยน ถ้าเก็บหน้าเก่าแล้วต่อหน้าใหม่อาจขาดหรือซ้ำ

**กด Cancel แล้วหยุด C อย่างไร?** UI ส่ง POST cancel; Python ต้องหยุดและรอ process แล้วตอบ cancelled ไม่ใช่แค่ UI หยุด polling

**ทำไม null ไม่เป็น 0?** null หมายถึงอ่านไม่ได้หรือยังสรุปไม่ได้ แต่ 0 หมายถึงขนาดที่วัดได้เป็นศูนย์

**อะไรที่พิสูจน์แล้ว?** ดู results.json, http-results.json และ review-results.json เป็นหลักฐาน UI, HTTP จำลอง และ Python/SQLite กับข้อมูลทดสอบ ส่วน Windows/WSL/full-drive ยังรอรวมงาน

## ก่อนนำเสนอจริง

1. รวม API ของปวริศช์และ C ของศรัณย์แล้วเปิดหน้า / บน Windows
2. ลองโฟลเดอร์เล็กจริง: Scan → กาง tree → แสดงเพิ่มเติม → Reveal
3. ลอง Cancel กับงานที่นานพอ ตรวจว่า process หยุดจริง
4. เก็บภาพจากโหมดจริงแทนภาพ mock พร้อมวันเวลาและเครื่องที่ใช้
5. เปิดผล full-drive ที่จบแล้วด้วยรหัสงาน ห้ามใช้ id mock เป็นหลักฐาน
6. เติมผลวัดจริงและข้อจำกัดลงหน้า 4/7 แล้วซ้อม 5–10 นาทีร่วมกัน 2 รอบ
