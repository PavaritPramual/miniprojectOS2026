# บทพูดสามคนและลำดับเดโม CoreSpace

อัปเดต 12 ตุลาคม 2569 สำหรับคลิปประมาณ 8 นาที ใช้โครง 9 หน้าจาก [แผนนำเสนอ](PRESENTATION_PLAN.md) เน้น OS และผล C → Python → เว็บจริงที่ตรวจแล้ว ไม่ใช่การสาธิต UI ด้วย simulator

ชื่อไฟล์เดิมคงไว้เพื่อให้ลิงก์ใช้งานต่อได้ เอกสารนี้เป็นบทซ้อมของทั้งสามคน ปรับน้ำเสียงได้ แต่ต้องคงความหมายและขอบเขตผลจริง

## แบ่งอัดและต่อคลิป

ธีรเมธอัดหน้า 1–2 และ 7–9 ศรัณย์อัดหน้า 3–4 ปวริศช์อัดหน้า 5–6 ต่อเป็นคลิปเดียวตามลำดับหน้า รวม 480 วินาทีโดยประมาณ ช่วงหน้า 7 เป็นการบันทึกหน้าจอจริงพร้อมเสียง ไม่ใช่การถ่ายภาพสไลด์นิ่งสองนาที เว้นจังหวะสั้นระหว่างหน้าและตัดความเงียบก่อนส่ง ไม่มีช่วงถามตอบสด

## หน้า 1 — หน้าปก

**ธีรเมธ · 15 วินาที**

สวัสดีครับ กลุ่มผู้ก้าวข้ามโชคชะตาด้วยมือของตัวเอง วันนี้นำเสนอ CoreSpace หัวข้อ Disk Space Visualization ครับ งานนี้ใช้ความรู้ OS อ่านข้อมูลไฟล์แล้วแสดงพื้นที่ผ่านเว็บ โดยมีศรัณย์ทำ C ปวริศช์ทำ Python และผมทำหน้าเว็บครับ

บนหน้าปกใส่สมาชิกครบ โดยศรัณย์ใช้รหัส **673380515-1** ปวริศช์ **673380278-9** และธีรเมธ **673380273-9** ไม่ต้องอ่านรหัสทุกคนออกเสียง

## หน้า 2 — OS ช่วยให้เรารู้ว่าโฟลเดอร์ใดใช้พื้นที่มาก

**ธีรเมธ · 40 วินาที**

เมื่อมีไฟล์กระจายหลายโฟลเดอร์ เราอาจไม่รู้ว่าอะไรใช้พื้นที่มาก งานนี้ให้เลือกโฟลเดอร์แล้วดูโครงสร้างและขนาดได้ครับ ตัวข้อมูลมาจากระบบปฏิบัติการ กราฟแท่งเปรียบเทียบขนาด Allocated สีเขียวคือโฟลเดอร์ สีน้ำเงินคือไฟล์ กดชื่อโฟลเดอร์เพื่อดูข้างในได้ ภาพนี้เป็นผล C และ Python จริงบน Windows แล้ว ต่อไปศรัณย์จะอธิบายว่าเราอ่านข้อมูลนั้นได้อย่างไรครับ

ชี้กราฟจริงว่า many ประมาณ 64.1% และ large.bin ประมาณ 35.9% ของยอดโฟลเดอร์ที่อ่านได้ ความยาวแท่งเทียบกับรายการใหญ่ที่สุด ไม่ใช่เปอร์เซ็นต์ความจุไดรฟ์ ไม่แจกแจงทุกปุ่ม

## หน้า 3 — อ่านขนาดไฟล์ได้โดยไม่ต้องอ่านเนื้อหาทั้งไฟล์

**ศรัณย์ · 60 วินาที**

ระบบไฟล์จัดเก็บชื่อและรายการใน directory ส่วนข้อมูลเกี่ยวกับไฟล์ เช่น ชนิดและขนาด เรียกว่า metadata ครับ โปรแกรมของเราเดินอ่านโฟลเดอร์และโฟลเดอร์ย่อย แล้วอ่าน metadata ของแต่ละรายการ ขนาดเนื้อหาอ่านจาก st_size จึงไม่ต้องเปิดอ่านเนื้อหาทั้งไฟล์เพื่อรู้ขนาด ข้อมูลนี้นำมาสร้าง tree และรวมขนาดของโฟลเดอร์ได้ครับ

ใช้ child-001.txt จาก fixture แบบ VariedSizes มี st_size 1,024 ไบต์ประกอบ แยก tree ที่เราแสดงออกจากการจัดเก็บภายในของระบบไฟล์ ไม่บอกว่า tree บนเว็บคือโครงสร้างบนดิสก์ทั้งหมด

## หน้า 4 — โปรแกรม C ขอข้อมูลไฟล์ผ่าน POSIX API

**ศรัณย์ · 70 วินาที**

ใน C เราใช้ opendir เปิด directory ใช้ readdir อ่านรายการ แล้วใช้ lstat อ่านชนิดกับขนาด โดย lstat ไม่ตาม symbolic link ไปยังปลายทาง เมื่อใช้เสร็จจะปิดด้วย closedir ครับ ถ้ามีข้อผิดพลาด โปรแกรมส่งเหตุผลกลับ ไม่ตีความว่าเป็นขนาดศูนย์ ลิงก์ที่ชี้กลับโฟลเดอร์เดิมจะถูกข้าม เพื่อป้องกันการเดินวนไม่จบ

ชื่อเหล่านี้เป็นส่วนติดต่อ POSIX ผ่านไลบรารีระบบ ไม่ได้แปลว่าการเรียกทุกฟังก์ชันตรงกับ kernel system call หนึ่งครั้ง การขอข้อมูลจาก kernel เกิดอยู่ภายในส่วนนี้ครับ ต่อไปปวริศช์จะอธิบายว่า Python รับผลจาก C อย่างไร

โชว์โค้ดจริงช่วงสั้น ๆ จาก `scanner/diskviz-scan.c` เน้นบรรทัดสำคัญ ห้ามบอกว่ามีผล strace ยืนยันแล้วหากยังไม่ได้เก็บหลักฐาน

## หน้า 5 — Python กับ C เป็นคนละ process และส่งข้อมูลผ่าน pipe

**ปวริศช์ · 70 วินาที**

เว็บส่งคำขอผ่าน HTTP ให้ Python บน Windows จากนั้น Python เปิดโปรแกรม C ใน Ubuntu ผ่าน WSL ซึ่งยังอยู่บนคอมเครื่องเดียวครับ C กับ Python เป็นคนละ process จึงส่งข้อมูลกันผ่าน pipe โดย C เขียน stdout ทีละบรรทัดเป็น NDJSON และ Python อ่านเพื่อตรวจและบันทึกลง SQLite

งานสแกนทำเบื้องหลัง เว็บจึงขอสถานะและรายการได้ระหว่างรอ เมื่อกดยกเลิก Python ส่ง TERM ไปยัง PID ของโปรแกรมใน Ubuntu ถ้าจำเป็นจึงใช้ KILL และตรวจว่าหยุดจริงก่อนรายงาน cancelled ไม่ใช่แค่หยุดถามสถานะบนเว็บครับ

ชี้ลูกศร HTTP กับ pipe คนละเส้น แยก background thread ของ Python ออกจาก process ของ C ไม่อ้างว่ามีอัลกอริทึม CPU scheduling ใหม่

## หน้า 6 — ขนาดเนื้อหากับพื้นที่ที่ใช้บนดิสก์อาจต่างกัน

**ปวริศช์ · 60 วินาที**

Logical คือขนาดเนื้อหาจาก metadata ที่ C อ่าน ส่วน Allocated ใช้ GetCompressedFileSizeW ของ Windows วัดครับ สองค่านี้อาจต่างกันจากวิธีจัดเก็บ เช่น ไฟล์บีบอัด แต่ไฟล์ตัวอย่างที่ตรวจในงานนี้ zero.bin ได้ศูนย์ทั้งสองค่า และ large.bin ได้ 1,048,576 ไบต์ทั้งสองค่า ซึ่งตรวจเทียบกับ Windows API อีกวิธีแล้ว

ยอดโฟลเดอร์รวมไฟล์ที่อ่านได้ทั้งหมด ไม่ใช่เฉพาะ 50 แถวที่เห็น ค่าศูนย์หมายถึงวัดได้ศูนย์ ส่วน null หมายถึงยังไม่ทราบหรือวัดไม่ได้ และยอดนี้อาจไม่เท่าพื้นที่ใช้ทั้งไดรฟ์ เพราะรายการที่อ่านไม่ได้ ข้อมูลระบบ และ hard link ครับ ต่อไปจะเปิดโปรแกรมให้ดูจริง

คำอธิบาย compressed/sparse เป็นทฤษฎี ไม่อ้างว่าได้ทดสอบกับไฟล์ชนิดนั้นแล้ว ไม่ใช้ Allocated ลบ Logical เป็น Slack เสมอ หลักฐานขนาดอยู่ใน [ผลรวมระบบ](results/REAL_SCANNER_INTEGRATION.md)

## หน้า 7 — เดโมจริง 2 นาที

**ธีรเมธ · 120 วินาที**

เปิดเว็บปกติที่ `http://127.0.0.1:8080` ไม่ใช้ `/?mock=1` ก่อนอัดต้องเปิดเซิร์ฟเวอร์และตั้ง C แล้ว ใช้ fixture ที่สร้างด้วย `tools/prepare_demo_fixture.ps1 -Target <โฟลเดอร์ใหม่> -VariedSizes` เตรียมอีกชุดด้วย `-IncludeJunction` และสแกนเก็บไว้ก่อน อัดเฉพาะหน้าต่างเว็บพร้อมเสียงอธิบาย

| เวลา | สิ่งที่ทำ | คำอธิบาย OS ที่พูด |
| --- | --- | --- |
| 00:00–00:30 | เลือก fixture ปกติแล้วกด Scan ดูจำนวนและสถานะ | Python เริ่ม process C และเว็บติดตามงานเบื้องหลัง ขนาดยังไม่ทราบจนได้รับข้อมูล |
| 00:30–01:00 | ชี้กราฟ many กับ large.bin กดโฟลเดอร์จากกราฟ ดูกราฟลูก แล้วแสดงเพิ่มเติมจาก 50 จนได้ 60 กาง tree สั้น ๆ | ขนาดมาจาก metadata/Windows API กราฟใช้รายการที่โหลดแล้ว เว็บไม่ต้องโหลดทั้งไดรฟ์ |
| 01:00–01:25 | กลับ root ดู zero.bin กับ large.bin และกด Reveal หนึ่งครั้ง | แยก metadata/ขนาดสองค่า และการเปิดตำแหน่งจากผลสแกน |
| 01:25–02:00 | เปิดผล fixture junction จริงที่เตรียมไว้ แล้วเปิด “ดูเหตุผลที่ข้อมูลไม่ครบ” | OS มีรายการชนิดลิงก์ โปรแกรมข้าม back-to-root ไม่เดินวน และแสดง partial อย่างตรงไปตรงมา |

คำพูดปิดเดโม: เราเห็นทั้งการอ่านข้อมูลไฟล์ การส่งข้อมูลระหว่าง process และการจัดการรายการที่ไม่เดินต่อ โดยผลที่ไม่ครบจะมีเหตุผลให้ตรวจครับ

### เมื่อบันทึกเดโมมีปัญหา

หากเริ่มสแกนไม่ได้ ให้แก้แล้วอัดช่วงนั้นใหม่ ไม่ใช้ mock แทนผลจริง หากผล junction ยังไม่ได้เตรียม ใช้ [ภาพเหตุผลจริง](results/real-web-issues.png) อธิบายเป็นภาพที่บันทึกไว้ได้ แต่ต้องบอกตรงว่าภาพไม่ใช่วิดีโอเดโม และหน้าเดโมยังรอไฟล์บันทึกหน้าจอจนกว่าจะอัดเสร็จ

ไม่เริ่มสแกนทั้งไดรฟ์ใหม่ระหว่างเดโมหลัก การยกเลิกเป็นหัวข้อที่อธิบายจากผลทดสอบได้ หากมีเวลาและเตรียมงานจริงที่ยังทำอยู่จึงสาธิตเพิ่ม ห้ามใช้ผล cancelled เป็นผลทั้งไดรฟ์ที่สแกนจบแล้ว

## หน้า 8 — ผลที่แสดงขึ้นอยู่กับรายการที่ OS อนุญาตให้อ่านได้

**ธีรเมธ · 40 วินาที**

ชุดโฟลเดอร์จริงรับครบ 64 ไฟล์และ 13 โฟลเดอร์ แบ่งรายการ 50 กับ 10 ได้ รวมทั้งชื่อไทยและความลึก 8 ชั้นครับ กราฟผ่านการตรวจ browser 7 กรณี ชุด Python ผ่าน 23 ข้อและข้าม 12 ข้อ โดย C tests 11 ข้อในนั้นรันใน Ubuntu แยกผ่านแล้ว อีกหนึ่งข้อเป็นการสแกนทั้งไดรฟ์ที่ไม่ได้เลือกเปิดในรอบนี้

ข้อจำกัดคือยอดรวมอ้างเฉพาะไฟล์ที่อ่านได้ เราตรวจสแกนไดรฟ์ D และยกเลิกสำเร็จ แต่ยังไม่ได้รอจนจบทั้งไดรฟ์ และไม่ได้ยืนยันทุกกรณีสิทธิ์ NTFS ครับ

ไม่ต้องอ่านรายชื่อเทสต์ทั้งหมด หากถูกถามเรื่องสิทธิ์ ให้แยก C tests บน Linux ออกจากสิทธิ์ NTFS บน Windows

## ก่อนอัดและก่อนส่งคลิป

1. เปิด C/Python/เว็บและลอง fixture หนึ่งรอบ เตรียมผล junction และตรวจ Reveal ก่อนอัด
2. ใช้ Canva 9 หน้าเป็นชุดเดียวกันทั้งสามคน ตรวจชื่อ รหัสสมาชิก ภาพจริง และไม่มีวันนำเสนอเก่าหรือข้อความรอ C
3. อัดเสียงตามส่วนของตน หน้า 7 อัดหน้าจอจริง 2 นาที ตัดต่อให้ครบทั้งสามคนโดยไม่อ่านทุกคำบนสไลด์

5. เตรียมคลิป demo/presentation และรายงานถ้ามี รอข้อมูลช่องทางและกำหนดส่งใหม่ ไม่ใช้กำหนดนำเสนอเดิมเป็นกำหนดส่งคลิป
