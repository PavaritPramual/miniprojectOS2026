# แก้รายการที่อ่านได้และข้อความอ่านไม่ได้

12 ตุลาคม 2569 ต่อจาก PR #7

## สิ่งที่พบจริง

ผลเก่าของ C:\ มี INVALID_ENTRY เพราะ relativePath ซ้ำ และ COUNT_MISMATCH ตามมา ข้อมูลเดิมไม่ได้เก็บชื่อของรายการที่ถูกปฏิเสธ จึงยังระบุไม่ได้ว่า C ส่งซ้ำเพราะเหตุใด ไม่ยืนยันว่าแก้ต้นเหตุ C แล้ว

ทดลองวัดพื้นที่ของรายการ ALLOCATED_SIZE_UNKNOWN เดิม 86 รายการใหม่บนเครื่องนี้ พบ 2 รายการคืนค่าพื้นที่ได้แล้ว และ 84 รายการคืน Windows error 1920 ทั้ง path ปกติและแบบ extended ไม่มีรายการในชุดเก่าที่กู้ได้ด้วย extended path ผลนี้เป็นการอ่าน metadata ซ้ำ ไม่ใช่การสแกนทั้งไดรฟ์ใหม่

## การแก้

- เทียบจำนวนท้ายงานกับจำนวน entry ที่รับและตรวจรูปแบบได้ เก็บไฟล์ซ้ำเพียงครั้งเดียวพร้อม DUPLICATE_ENTRY และ path ไม่รวมขนาดซ้ำ ยังเป็นผลบางส่วน ไม่กลืนข้อผิดพลาด
- INVALID_ENTRY เก็บ path ที่ปลอดภัยเพื่อช่วยตรวจต้นเหตุ
- ใช้ extended Windows path สำหรับ GetCompressedFileSizeW รองรับชื่อ path ยาวโดยไม่ต้องเปลี่ยนการตั้งค่าเครื่อง
- เมื่อวัดไม่ได้ แสดงเหตุผลและ Windows error จริง เช่น ถูกล็อก ไม่พบไฟล์ ไม่มีสิทธิ์ หรือเข้าถึงไฟล์ไม่ได้ ค่าไม่ทราบยังเป็น null

[Microsoft GetCompressedFileSizeW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getcompressedfilesizew) ระบุการใช้ extended path และ GetLastError สำหรับแยกความล้มเหลวออกจากค่าขนาดที่ถูกต้อง

## ผลตรวจ

- Python backend/search 20 tests ผ่าน รวมรายการซ้ำใน batch เดียวและข้าม batch ยอดไม่ซ้ำ การรักษาข้อผิดพลาดจำนวนไม่ตรงจริง และไฟล์ path ยาวเกิน 260 ตัวอักษรที่สร้างและวัดจริงบน Windows
- ชุด C จริง 3 tests: ผ่าน 2 ข้าม 1 กรณี whole-drive ที่ต้องเลือกเปิดต่างหาก ไม่อ้างว่าทดสอบไดรฟ์ครบแล้ว
- ไม่แก้สิทธิ์ Windows ไม่เดินตาม junction และไม่เปลี่ยนผลสแกนเก่าที่บันทึกไว้ ต้องสแกนใหม่เพื่อรับรายละเอียดข้อผิดพลาดรุ่นใหม่

ยังต้องจับข้อมูลจาก C หากรายการซ้ำเกิดอีกเพื่อหาต้นเหตุ ฝั่ง Python รอบนี้เก็บข้อมูลไม่ซ้ำและแจ้ง path ให้ตรวจได้
