# ผลตรวจ C จริง → Python → เว็บ

ตรวจวันที่ 6 ตุลาคม 2569 บน Windows เครื่องกลุ่ม ใช้ Windows Python 3.12.14 และ Ubuntu ใน WSL โปรแกรม C จาก PR #3 ที่ merge เป็น `feb6021` ไม่มี benchmark หรือการเปรียบเทียบกับต้นแบบ

## สิ่งที่เปลี่ยนในรอบนี้

- Python ตอบข้อมูล root ระหว่างรอ C ได้โดยขนาดเป็น `null` แก้ข้อความโหลดไม่สำเร็จช่วงเริ่มงาน โดยไม่เพิ่ม API หรือช่องข้อมูล
- สคริปต์สร้างโฟลเดอร์ทดสอบใช้ UTF-8 พร้อม BOM เพื่อให้ Windows PowerShell 5 อ่านชื่อไทยได้ตรงกับ PowerShell 7
- เพิ่มชุดตรวจ C จริงผ่าน HTTP แยกจากโปรแกรมจำลอง ใช้ฐานข้อมูลและโฟลเดอร์ชั่วคราว และเลือกสแกนทั้งไดรฟ์เองเท่านั้น

## ตรวจซ้ำ

เปิด PowerShell ที่ root ของโปรเจกต์ ใช้ Windows Python ที่ติดตั้งจริงแทน `python` หากไม่อยู่ใน PATH:

```powershell
python tools/run_checks.py --wsl --real-scanner-wsl-path '/home/ชื่อผู้ใช้/.local/bin/diskviz-scan' --output docs/results/real-scanner-tests.txt
```

เพิ่ม `--drive 'D:\'` เฉพาะเมื่อต้องการทดสอบสแกนและยกเลิกไดรฟ์ D จริง คำสั่งไม่ได้ลบไฟล์ในไดรฟ์ แต่จะอ่านข้อมูลจนกว่าจะตรวจการยกเลิกเสร็จ โปรแกรมจำลอง WSL ยังต้องใช้ fixture เดิมที่สร้างด้วย `tools/prepare_demo_fixture.ps1` หากยังไม่มี

ใน Ubuntu:

```bash
python3 -m unittest tests.test_c_scanner -v
```

## ข้อจำกัดและงานส่งต่อ

- สแกนไดรฟ์ D ถึงขั้นยกเลิก ไม่ได้รอจบทั้งไดรฟ์ จึงไม่มีผลยอดทั้งไดรฟ์ที่ยืนยันว่าครบ หากต้องการแสดงผลไดรฟ์ที่จบแล้วในวันนำเสนอ ต้องสแกนเก็บไว้เพิ่ม
- ชุด C ตรวจรายการอ่านไม่ได้ใน Linux; ไม่ได้ยืนยันทุกกรณีสิทธิ์ NTFS ของ Windows และไม่ได้ทดสอบ drive C ทั้งลูก
- ก่อนแก้ root พบ HTTP 404 ชั่วคราวตอนเริ่มงาน แก้ฝั่ง Python แล้ว ตรวจเว็บซ้ำไม่เกิด 404 ของ root ใหม่ ส่วน 404 ของ Reveal ไฟล์ที่ลบเป็นผลที่คาดไว้ และ favicon.ico ยังตอบ 404 ไม่มี JavaScript exception ที่พบระหว่างตรวจ
- ยอดโฟลเดอร์เป็นผลรวมไฟล์ที่อ่านได้ ไม่ใช่ยอดใช้พื้นที่ทั้งหมดของไดรฟ์ ค่าขนาดที่เท่ากันใน fixture นี้ไม่ได้หมายความว่า Logical และ Allocated จะเท่ากันทุกไฟล์
- รอบนี้ไม่แก้ C หรือหน้าเว็บ และไม่รวมการแก้เดิมใน `backend/aggregator.py` สมาชิกแต่ละคนยังดูแลส่วนของตนเอง
